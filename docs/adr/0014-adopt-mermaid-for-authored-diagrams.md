# 0014 – Adopt Mermaid for Authored Diagrams

**Date:** 2026-10-24  
**Status:** Accepted (amends ADR 0009)

## Context

Money Priorities shows the Priority Tree: a fixed, authored set of questions and outcomes, with the path the ApiService
computed from a Priority Walk highlighted. The owner draws such trees in Mermaid and requires it. ADR 0009 gives the app
two drawing tools, Chart.js for data charts and D3 for pictures the user manipulates; neither is a tool for a diagram
whose structure is the content and is authored as text.

## Decision

1. **Mermaid is the third drawing tool, for authored-structure diagrams only.** The Priority Tree is the first. Chart.js
   stays the default for data charts and D3 for direct manipulation (ADR 0009). Mermaid never draws a data chart.
2. **Diagram text is generated by the app from an authored model, never from user input.** The model is the source of
   truth, so the picture and the computed path cannot disagree. Purposes, amounts and every other user-entered value
   appear only in the page's HTML, never in diagram text. `securityLevel: 'strict'` stays on as a second guard.
3. **Pinned exactly: `mermaid@11.17.2`, vendored through libman from jsDelivr** at `wwwroot/lib/mermaid/dist/mermaid.min.js`.
   jsDelivr mirrors the npm release the maintainers publish, byte for byte and immutably; cdnjs repackages it and stalled
   at 11.15.0. jsDelivr is the source of record for libman packages that cdnjs lags.
4. **Loaded only on pages that use it**, from the view's `Scripts` section, never from `_Layout`. At about 1 MB gzipped
   it is the app's heaviest asset.
5. **One configuration:** `startOnLoad: false`, `theme: 'base'`, `look: 'classic'`, dagre layout, `securityLevel:
   'strict'`. Colours are hex values in a palette passed to the generator, because Mermaid bakes them into the SVG; a
   theme change re-renders.
6. **Re-render by rendering offscreen and swapping once:** `mermaid.render(freshId, text)` with no container, then one
   `innerHTML` assignment. Highlight styling (`classDef`/`class` on nodes, `linkStyle` by edge index) lives in the
   generated text, because external CSS cannot override Mermaid's id-scoped styles.
7. **A major upgrade is its own pull request** that reruns the visual, accessibility and leak checks from the re-render
   prototype (`research/money-priorities-rerender`).

## Considered Options

- **Draw the tree with D3:** rejected. D3 would need a hand-built tree layout, and the owner authors these trees in
  Mermaid.
- **A static SVG exported from Mermaid at build time:** rejected. The highlighted path differs per Priority Walk, so it
  needs a render per path, or styling the static SVG from CSS, which Mermaid's id-scoped styles prevent.
- **Render on the server with mermaid-cli:** rejected. It needs a headless browser in the ApiService.
- **Mermaid 12:** rejected for now. It is about 600 KB larger, requires Safari 17.4 or later, and changes the default look
  and layout.
- **11.15.0 from cdnjs:** rejected. It is three months of fixes behind 11.17.2, and cdnjs updates for Mermaid have stalled.

## Consequences

- ADR 0009's Status line reads "amended by ADR 0014 (Mermaid for authored diagrams)". Its body stays as written.
- `libman.json` gains the `mermaid@11.17.2` jsDelivr entry, and the vendored file is committed like the others.
- Mermaid is MIT, within the licence policy.
